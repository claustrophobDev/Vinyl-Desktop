# Vinyl для Windows

Портативный VPN-клиент на sing-box. Тот же Vinyl, что и на телефоне, только под винду и написан на C++.

Скачал папку, распаковал, запустил `vinyl.exe` — всё. Конфиг, логи и список серверов лежат рядом с exe,
в систему ничего не размазывается. Из системного только ярлык в меню пуск и строчка в «Программы и компоненты»,
чтобы программа находилась поиском винды. Убирается это через `uninstall.exe` рядом.

## Что умеет

- VLESS (в том числе Reality и XTLS Vision), VMess, Trojan, Shadowsocks, Hysteria2, TUIC, WireGuard
- Подписки: обновление, остаток трафика и дата окончания, если панель их отдаёт
- Разделение трафика по программам: «Все», «Только выбранные», «Кроме выбранных»
- Свои сайты мимо VPN + готовые наборы (банки с госуслугами, российские сайты)
- Автовыбор сервера по пингу
- Скорость и трафик в реальном времени
- Иконка в трее, подключение и выход прямо из меню
- Автозапуск вместе с виндой

## Как собрать

Нужны Visual Studio с C++ (проверял на 2026, но подойдёт и 2022), CMake и Windows SDK.

Зависимости лежат отдельно от проекта, по умолчанию в `E:\dev\deps`:

```
E:\dev\deps\
  nlohmann-json\json.hpp
  sing-box-1.14.0-windows-amd64\sing-box.exe
  wintun\bin\amd64\wintun.dll
```

Путь можно поменять через `VINYL_DEPS_DIR`.

```bash
cmake -S . -B build
cmake --build build
```

На время отладки удобно собирать без запроса прав администратора, иначе UAC вылезает на каждый запуск:

```bash
cmake -S . -B build -DVINYL_REQUIRE_ADMIN=OFF
```

Собрать готовую к раздаче версию:

```bash
powershell -ExecutionPolicy Bypass -File tools\pack.ps1
```

Скрипт соберёт релиз (обязательно с правами администратора, иначе не поднимется tun-интерфейс),
разложит всё по местам и заодно сделает архив:

```
outputs\
  Vinyl-1.0.0\
    vinyl.exe
    uninstall.exe
    Как пользоваться.txt
    core\      sing-box.exe и wintun.dll
    data\      сюда лягут настройки и логи
  Vinyl-1.0.0.zip
```

Версия берётся из `kVersion` в `src/app/Install.h`, так что имя папки меняется вместе с ней.
Архив можно сразу заливать: распаковал и запустил, искать зависимости не надо.

## Как устроено

Сам туннель поднимает `sing-box.exe`, он лежит в папке `core` рядом с программой и запускается отдельным
процессом. Программа собирает ему конфиг и следит, чтобы он не остался висеть: процесс кладётся в job-объект
с `KILL_ON_JOB_CLOSE`, так что если окно упадёт, туннель закроется вместе с ним.

```
src/
  core/      разбор ссылок и сборка конфига для sing-box
  data/      модели и файл состояния
  net/       http для подписок, tcp-пинг
  vpn/       запуск ядра и счётчики трафика
  ui/        отрисовка на Direct2D
  ui/views/  по классу на экран: Home, Servers, Routes, Settings
  app/       модель приложения, пути, лог, автозапуск, регистрация в системе
tests/
  UnitTests.cpp     тесты на логику, запускаются через ctest
  CheckConfig.cpp   складывает конфиги на диск, чтобы проверить их настоящим sing-box check
```

Окно занимается только рамкой, боковым меню, треем и полем ввода. Экраны в `ui/views` ничего
не меняют сами: они получают `ViewContext`, рисуют и складывают зоны для кликов, а что делать
с нажатием — решает окно.

Тесты:

```bash
ctest --test-dir build --output-on-failure
```

Их два. `logic` — чистые проверки без окон и сети: строки, разбор всех типов ссылок, сборка
конфига, флаги, чтение и запись состояния. `core_stop` поднимает настоящее ядро на безопасном
конфиге (без tun, маршруты системы не трогаются) и проверяет, что оно закрывается само по
ctrl+break, а не через `TerminateProcess`. Если ядра рядом нет, тест пропускается.

У `vinyl_check` есть ещё два режима для ручной отладки:

```bash
build\vinyl_check.exe --sub https://.../sub     что ответила панель и сколько серверов разобралось
build\vinyl_check.exe --vpn "vless://..." 10    поднять настоящий туннель на 10 секунд (нужен админ)
```

Интерфейс рисуется вручную через Direct2D, без всяких фреймворков: окно без стандартной рамки,
свой заголовок, всё перерисовывается каждый кадр. Так проще всего было повторить оформление мобильной версии
один в один.

### Про разделение трафика

На андроиде это делалось списками пакетов прямо в настройках tun-интерфейса. В винде так нельзя,
поэтому трафик делится правилами маршрутизации по имени процесса:

```json
{ "process_name": ["telegram.exe", "chrome.exe"], "outbound": "proxy" }
```

В режиме «Только выбранные» весь остальной трафик идёт напрямую, поэтому `route.final` переключается
на `direct`, а не на прокси.

### Проверка конфигов

`vinyl_check.exe` берёт набор ссылок на все поддерживаемые протоколы, прогоняет их через парсер и
складывает готовые конфиги в папку. Дальше их можно проверить настоящим ядром:

```bash
build\vinyl_check.exe build\configs
build\core\sing-box.exe check -c build\configs\vless-reality.json
```

Ключи в тестовых ссылках выдуманные, но правильной длины — ядро декодирует их из base64 и требует ровно
32 байта, иначе конфиг не пройдёт проверку.

## Чего нет

XHTTP (он же SplitHTTP) и mKCP ядро sing-box не поддерживает. Такие серверы в списке видно, но они серые
и подключиться к ним нельзя. Это не лень, это ограничение ядра — в Happ подобное работает потому, что там
внутри Xray, а не sing-box.
